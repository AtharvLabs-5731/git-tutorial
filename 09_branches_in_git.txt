1. What is a Branch in Git?
    A branch in Git is like a separate line of development where we can make changes without affecting the main code.

Think of it like this:
    main
    |
    A
    |
    B
    |
    C

Now we create a new branch:
             D
           /
    A --- B --- C        main
           \
             D --- E      feature
The feature branch allows us to work on a new feature independently.

Simple definition
    A branch is a movable pointer to a commit that provides an independent line of development.

2. Why Do We Use Branches?

Branches are mainly used to:
    Develop new features separately
    Fix bugs without disturbing the main code
    Experiment with changes
    Allow multiple developers to work simultaneously
    Keep the main branch stable

Real-life example
Suppose we have a website:
    main → Working website
We want to add a login system.

Instead of directly changing main:
    main
    ↓
    Change login
    ↓
    Something breaks ❌

We create a branch:
    main
    |
    +---- login-feature
We develop the login system on login-feature.

After testing:
    login-feature
        |
        ↓
        merge
        |
        ↓
        main

3. Main Branch
The main branch is usually called:
    main
Older Git repositories commonly used:
    master
Today, main is the common default name.
The main branch generally contains the stable/production-ready code.

4. Check Current Branch
    git branch
Example:
    * main
    feature-login
    bug-fix
The * indicates the branch you are currently on.

Another useful command:
    git status
It also shows the current branch.

5. Create a New Branch
    git branch feature-login
This creates the branch, but does not switch to it.

Check:
    git branch

Output:
    * main
    feature-login
You are still on main.

6. Switch to Another Branch
    git switch feature-login
Now:
    main
    feature-login  ← current branch

You can also use the older command:
    git checkout feature-login

7. Create + Switch to Branch in One Command

Modern Git:
    git switch -c feature-login

Older Git:
    git checkout -b feature-login

This does two things:
    Create branch
        +
    Switch to branch

9. Important Concept: Branch Does NOT Create a Full Copy
A common misunderstanding is:
    "When I create a branch, Git creates a complete copy of my project."
Not exactly.
A branch is basically a pointer/reference to a commit.

Example:
                main
                ↓
    A --- B --- C

Create a branch:
                main
                ↓
    A --- B --- C
                ↑
                feature
Both branches initially point to the same commit C.

When we make a new commit on feature:

                main
                ↓
    A --- B --- C
                 \
                  D
                  ↑
                  feature
Now the branches point to different commits.

10. Merge a Branch
After finishing the feature, we can merge it into main.

First switch to main:
    git switch main
Then:
    git merge feature-login

Example:
Before merge:
    A --- B --- C        main
                 \
                  D --- E    feature-login

After merge:
    A --- B --- C --- D --- E    main
Depending on the commit history, Git may create a merge commit instead.

Example:

            D --- E
           /        \
    A --- B --- C --- M
                      ↑
                      main

11. Delete a Branch
After merging, we usually delete the branch:
    git branch -d feature-login
-d means delete the local branch.

If Git refuses because the branch has unmerged changes:
    git branch -D feature-login
⚠️ -D force deletes the branch.

12. Rename a Branch
Rename the current branch:
    git branch -m new-name

Example:
    git branch -m feature-login

13. Branch Naming Convention
Use meaningful branch names.
Good:
    feature-login
    feature-payment
    bugfix-navbar
    bugfix-login-error
    database-update

Avoid:
    abc
    test
    new
    branch1
    xyz

Common prefixes:
    feature/...
    bugfix/...
    hotfix/...
    release/...

Example:
    feature/login
    feature/payment
    bugfix/navbar

14. Local Branch vs Remote Branch
Local branch
Exists on your computer:
    main
    feature-login

Remote branch
Exists on a remote repository such as GitHub:
    origin/main
    origin/feature-login

Here:
    origin
usually represents your GitHub repository.

15. See All Branches
Local branches
    git branch
Remote branches
    git branch -r
Local + remote branches
    git branch -a

16. Branch Example with Multiple Developers
Suppose a team has:
    main

Developer 1:
    feature/login

Developer 2:
    feature/payment

Developer 3:
    bugfix/cart

Structure:
                      feature/login
                     /
    main ----------+
                     \
                      feature/payment

                     \
                      bugfix/cart
Everyone can work independently.

After completing their work:
    feature/login
          ↓
        merge
          ↓
        main

    feature/payment
          ↓
        merge
          ↓
        main
This makes collaborative development much easier.

20. Important Commands Summary
Command	                                        Purpose
git branch	                                    Show local branches
git branch branch-name	                        Create a branch
git switch branch-name	                        Switch branch
git switch -c branch-name	                    Create and switch
git checkout branch-name	                    Older way to switch
git checkout -b branch-name	                    Older way to create + switch
git merge branch-name	                        Merge branch
git branch -d branch-name	                    Delete branch
git branch -D branch-name	                    Force delete branch
git branch -m new-name	                        Rename branch
git branch -r	                                Show remote branches
git branch -a	                                Show all branches
