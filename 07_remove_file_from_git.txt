Manually deleting file can risky because by deleting the file by git it will initally move it to staged area and then after commiting it It will remove the file 

1. Removing Files from Git
There are two different situations:
A1. Delete the file completely
    git rm file.txt
This does two things:
    Git Repository  → removes file
    Working Folder  → removes file
Then commit:
    git commit -m "Remove file.txt"

Example
Suppose you have:
    project/
    ├── main.cpp
    ├── notes.txt
    └── password.txt
You want to completely delete notes.txt.
    git rm notes.txt
    git commit -m "Remove notes.txt"
After this:
    project/
    ├── main.cpp
    └── password.txt
notes.txt is gone from your working directory and Git's tracked version.

A2. Delete the file & then again regain the file before commiting it
    git rm file.txt
then 
git status will show me :
    On branch master
    Changes to be committed:
        (use "git restore --staged <file>..." to unstage)
            deleted:    notes.txt
then do 
    git restore --staged file.txt
then git status will show me : 
    Changes not staged for commit:
        (use "git add <file>..." to update what will be committed)
        (use "git restore <file>..." to discard changes in working directory)
            modified:   07_remove_file_from_git.txt
            deleted:    notes.txt
so to restore the file do :
    git restore file.txt

2. Remove from Git but Keep the File
    git rm --cached file.txt
    git commit -m "Stop tracking file.txt"
This is useful when you accidentally committed a file that should be ignored.


This is where --cached becomes important.
    git rm --cached file.txt
This means:
    "Git, stop tracking this file, but don't delete my actual file."
So:
    Git Repository  → ❌ Stop tracking
    Working Folder  → ✅ Keep file

Example
You accidentally committed:
    .env
Your .env contains:
    DB_PASSWORD=abc123
    API_KEY=xyz456
You don't want GitHub to track it.
First:
    git rm --cached .env
Then add it to .gitignore:
    echo ".env" >> .gitignore  ---> It sometimes not work properly
Then:
    git add .gitignore
    git commit -m "Stop tracking .env"
Now:
    .env
    │
    ├── Your computer → ✅ Still exists
    │
    └── Git → ❌ No longer tracked
⚠️ Important
If the secret was already pushed to GitHub, git rm --cached does not erase it from the repository's history. For real credentials, you should rotate/revoke them and, if necessary, clean the Git history.

3. git restore --staged
Now let's look at this:
    git restore --staged passwords.txt
This is different from git rm --cached.

Suppose:
    git add passwords.txt
You accidentally staged it.
Your situation is:
    Working Directory
        ↓
    passwords.txt
        ↓
    Staging Area
        ↓
    passwords.txt
You realize:
    "Oops! I don't want to commit this yet."
Run:
    git restore --staged passwords.txt
Now:
    Working Directory
        ↓
    passwords.txt ✅

    Staging Area
        ↓
    passwords.txt ❌
The file still exists on your computer and Git hasn't deleted it.
You're simply saying:
    "Remove this file from the staging area."

4. Difference: git restore --staged vs git rm --cached
This is a very important distinction.

Command                             Working file                                 Staging/Tracking
git restore --staged file.txt	    ✅ Keeps	                                   ❌ Removes from staging
git rm --cached file.txt	        ✅ Keeps	                                   ❌ Removes from tracking
git rm file.txt	                    ❌ Deletes	                               ❌ Removes from tracking

Think about it this way:
    git restore --staged
            ↓
    "I don't want to commit this RIGHT NOW."

    git rm --cached
            ↓
    "Git should STOP TRACKING this file."

    git rm
            ↓
    "Delete this file completely."

5. Moving/Renaming Files
You can rename a file using:
    git mv oldname.txt newname.txt

For example:
    git mv test.txt notes.txt
Then:
    git commit -m "Rename test.txt to notes.txt"
Git understands that the file was renamed.
Conceptually:
    test.txt
        ↓
        ↓ git mv
        ↓
    notes.txt

Git tracks file movements:
    git mv oldname.txt newname.txt
    git commit -m "Rename oldname.txt to newname.txt"
This is equivalent to:
    mv oldname.txt newname.txt
    git rm oldname.txt
    git add newname.txt

Practical Examples
Example 1: Fixing a Mistake
    # You accidentally staged a file
    git add passwords.txt
    
    # Unstage it
    git restore --staged passwords.txt
    
    # Add it to .gitignore
    echo "passwords.txt" >> .gitignore
    
    # Stage and commit .gitignore
    git add .gitignore
    git commit -m "Add .gitignore to exclude sensitive files"

Example 2: Cleaning Up Working Directory
    # See what's changed
    git status
    
    # Review the changes
    git diff
    
    # Discard changes to a specific file
    git restore style.css
    
    # Or discard all changes
    git restore .
