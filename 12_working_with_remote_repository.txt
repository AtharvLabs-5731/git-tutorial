1. After Making Changes Locally
Suppose you changed README.md and then:
    git add README.md
    git commit -m "Update README"

    git status
You may see:
    On branch main
    Your branch is ahead of 'origin/main' by 1 commit.
    (use "git push" to publish your local commits)

    nothing to commit, working tree clean

What does this mean?
On branch main
You are currently working on the main branch.
ahead of 'origin/main' by 1 commit
Your local repository has 1 new commit that has not yet been uploaded to GitHub.
    Local main
        ↓
    Commit 3  ← new commit
        ↓
    Commit 2

    GitHub origin/main
        ↓
    Commit 2
So you need:
    git push
nothing to commit, working tree clean
There are no uncommitted changes.

It means:
    Working files ✅
    Staged files  ✅
    Committed    ✅

2. Push Changes
First Push
    git push -u origin main

-u sets the upstream relationship between:
    local main ↔ origin/main

After that, normally you can simply use:
    git push
Regular Push
    git push
Uploads your local commits to the remote repository.

Push a Specific Branch
    git push origin branch-name

Example:
    git push origin feature-login
This pushes the feature-login branch to GitHub.

3. Someone Else Changes GitHub Repository
Suppose someone edits your README.md directly on GitHub and commits the change.
Your local repository does not automatically download that change.

Important point
Running:
    git status
does not necessarily mean GitHub currently has no new changes.

You may see:
    Your branch is up to date with 'origin/main'.
This means your local main is up to date with your last known origin/main information.
origin/main is your local reference to the remote branch. You generally need fetch or pull to discover newly pushed remote commits.

4. git pull
    git pull
git pull basically performs:
    git fetch
        ↓
    git merge

So:
    GitHub
    ↓ fetch
    Local remote-tracking branch
    ↓ merge
    Local main
It downloads the latest changes and merges them into your current branch.

Pull Specific Branch
    git pull origin branch-name
Example:
    git pull origin main

5. git fetch
    git fetch
Fetches the latest commits from the remote repository without merging them into your current branch.

Think:
    GitHub
    ↓
    origin/main
Your local main is not changed yet.
This lets you first inspect the changes and then decide whether to merge.

Fetch All Remotes
    git fetch --all
Fetches updates from all configured remotes.

6. git fetch + git merge
Instead of:
    git pull

you can do:
    git fetch
    git merge origin/main
This gives you more control.

Difference
git pull
    = fetch + merge

git fetch
    = fetch only

git fetch + git merge
    = fetch first, merge separately

7. Remote Branches
To see remote branches:
    git branch -r

Example:
    origin/main
    origin/development
    origin/feature-login
These are branches that exist on the remote repository.

origin/main
    origin → remote name
    main   → branch name

8. Delete a Remote Branch
    git push origin --delete branch-name

Example:
    git push origin --delete feature-login

This deletes the branch from GitHub.
    Local branch        → may still exist
    Remote branch       → deleted
